# 调用记录 · 列表与详情各自滚动验收

交付日期：2026-10-19。数据来自隔离库（12 技能 / 40 条调用记录）在无头 Chrome 下的实测。

## 行为

- ≥1024px 并排布局下，整页不再滚动：页面正好填满可视区，页头 / 统计 / 筛选常驻不动。
- 左侧记录列表是独立滚动容器：页签固定在列表上方，分页固定在下方，只有中间的行会滚；列头在滚动时吸顶。
- 右侧「记录详情」是独立滚动容器：标题固定，正文（调用概况、调用位置、证据、来源文件等长内容）在面板内滚动，长路径也能滚到底。
- 两个面板各自有滚动条（细滚动条，10px 轨道、悬停加深），互不影响；滚轮落在哪一侧就只滚那一侧。
- <1024px 窄窗口保持原有行为：详情落到列表下方，整页一起滚，不出现嵌套滚动。

## 实测（1600×700）

| 观察项 | 结果 |
| --- | --- |
| 整页滚动量 | `scrollHeight 700 == clientHeight 700`，无整页滚动 |
| 左列表 | 内容 1744 / 可视 189（可滚） |
| 右详情 | 内容 582 / 可视 233（可滚） |
| 在左列表滚 420 | 列表 0 → 420；详情 0 → 0；页面 0 |
| 在右详情滚 420 | 详情 0 → 349；列表 420 → 420；页面 0 |
| 列头 | `position: sticky`，滚动 420 后仍贴在列表顶部 |
| 页签 / 分页 | 都在滚动区之外，位置不变 |
| 1600×950 | 列表可视 439px，约 7 行 |
| 900 宽 | 整页 2902/800 可滚，两栏不可滚（回退正确） |

## 边界

- 已选记录时详情才有内容；未选时只显示占位文案，此时右侧不可滚。
- 窗口高度较小时（如 700px），页头+统计+筛选约占 370px，列表可视高度只剩约 190px（3 行）。若需要，可给主区加 `min-h` 让页面在高窗口下回到整页滚动，代价是出现第三种滚动。
- 细滚动条样式新增全局 `.scroll-area`，目前只用在调用记录这两处。
- 未重新打包 Windows EXE。
